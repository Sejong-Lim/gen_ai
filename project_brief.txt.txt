# 프로젝트 목적

나는 설비이상감지시스템 VOC 응답 Agent를 만들고 싶다.

이 시스템은 반도체/제조 현장의 엔지니어들이 사용하는 설비 이상 감지 플랫폼이다.
엔지니어는 시스템 사용 중 발생한 문의사항, 오류, 알람 해석 요청, 데이터 조회 문제, 설정 변경 요청 등을 VOC로 등록한다.
Agent는 기업 내부 매뉴얼, 운영 가이드, 장애 대응 문서, FAQ, VOC 이력 데이터를 기반으로 답변을 자동 생성해야 한다.

# 가상의 시스템 이름

FDC-Monitoring AI System

# 주요 사용자

- 설비 엔지니어
- 공정 엔지니어
- 운영 담당자
- 현장 대응 담당자

# 주요 기능

- 설비 센서 데이터 모니터링
- 이상 감지 알람 발생
- 알람 원인 추정
- 설비별 Trend Chart 조회
- Recipe / Lot / Chamber 기준 검색
- 알람 임계치 설정
- 알람 이력 조회
- VOC 등록 및 처리 상태 확인

# 생성해야 할 가짜 데이터

다음 데이터를 만들어줘.

1. 기업 내부 매뉴얼 문서
- 시스템 사용 매뉴얼
- 알람 코드 설명서
- 장애 대응 가이드
- FAQ 문서
- 운영 정책 문서

2. VOC 데이터
- 엔지니어가 등록한 문의사항 100건
- 각 VOC에는 다음 필드를 포함
  - voc_id
  - title
  - content
  - user_role
  - equipment_id
  - alarm_code
  - category
  - priority
  - created_at
  - expected_answer
  - source_document_hint

3. DB 샘플 데이터
- 설비 목록
- 알람 코드 목록
- 사용자 목록
- VOC 처리 이력
- 알람 발생 이력

# VOC 카테고리 예시

- 알람 원인 문의
- Trend Chart 조회 오류
- 데이터 누락 문의
- 임계치 설정 문의
- 설비 상태 불일치
- 권한 문제
- 시스템 접속 오류
- 알람 코드 의미 문의
- 조치 방법 문의
- VOC 처리 상태 문의

# 답변 Agent 요구사항

Agent는 답변할 때 반드시 다음 형식을 지켜야 한다.

1. 요약 답변
2. 근거 문서
3. 상세 설명
4. 권장 조치
5. 추가 확인 질문
6. 신뢰도 점수

문서에서 근거를 찾지 못하면 추측하지 말고
"현재 지식베이스에서 근거를 찾을 수 없습니다"라고 답변해야 한다.

# 중요한 조건

- 모든 데이터는 가짜지만 실제 기업 시스템처럼 일관성 있게 만들어줘.
- VOC 질문과 매뉴얼 내용이 서로 연결되게 만들어줘.
- RAG 검색 테스트가 가능하도록 문서 안에 구체적인 알람 코드, 설비 ID, 조치 절차를 포함해줘.
- 일부 VOC는 문서에 근거가 부족한 케이스로 만들어서 hallucination 방지 테스트가 가능하게 해줘.
