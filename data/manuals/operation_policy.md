## POL-PERM-002 | 임계치 변경 권한 상세

임계치(threshold) 변경은 본 시스템의 알람 발생 거동을 직접 변경하므로 별도 권한 통제가 필요합니다.

**원칙**
1. **신청**은 EQ_ENG 이상이 가능하나, **승인**은 PROC_ENG 이상만 가능합니다.
2. **Critical 알람의 임계치**는 PROC_ENG 단독 승인이 아닌 **공정 PM 추가 승인**이 필요합니다.
3. **EHS와 연계된 알람(GAS-C-001 등)의 임계치**는 **EHS 부서 승인**이 추가로 필요합니다.
4. 변경 후 **최소 24시간 모니터링** 의무가 신청자에게 부여됩니다.

**Severity 별 추가 승인 요건**

| Severity | 신청자 | 1차 승인 | 추가 승인 |
|---|---|---|---|
| Critical (C) | EQ_ENG / PROC_ENG | PROC_ENG | 공정 PM (+EHS 연계 시 EHS) |
| High (H) | EQ_ENG / PROC_ENG | PROC_ENG | — |
| Medium (M) | EQ_ENG / PROC_ENG | PROC_ENG | — |
| Warning (W) | EQ_ENG / PROC_ENG | PROC_ENG | — |
| Info (I) | EQ_ENG | EQ_ENG 팀장 | — |

## POL-SLA-001 | VOC 처리 SLA

VOC 등록 후 처리 단계별 SLA(목표 응답 시간):

| Severity / Priority | 1차 응답 (assignee 배정) | 1차 조치 시작 | 종결 목표 |
|---|---|---|---|
| URGENT (라인 정지) | 5분 | 15분 | 4시간 |
| HIGH | 30분 | 2시간 | 24시간 |
| NORMAL | 4시간 | 24시간 | 5영업일 |
| LOW | 24시간 | 5영업일 | 10영업일 |

**SLA 측정 기준**
- 측정 시각은 정규시간(09:00-18:00) 기준이며, 야간/주말은 별도 ([POL-NIGHT-001]).
- 위 SLA를 충족하지 못하면 자동 escalation 알림이 팀장에게 전송됩니다.
- SLA 미준수 사례는 월간 운영 리포트에 자동 집계됩니다.

## POL-ESC-001 | 내부 Escalation 절차

내부 escalation은 **3단계**입니다.

1. **1차 — EQ_ENG (담당 엔지니어)**: VOC 등록 즉시 자동 배정. 본인 처리 가능 여부 30분 이내 판단.
2. **2차 — 팀장**: EQ_ENG가 30분 이내 처리 불가 판단 또는 SLA 1차 응답 미충족 시 자동 escalation.
3. **3차 — 공정 PM**: 팀장 30분 이내 응답 불가 또는 라인 정지 영향 발생 시.

**자동 escalation 트리거**
- 1차 응답 SLA 초과
- Critical 알람과 연계된 VOC는 즉시 2차로 동시 통보
- URGENT priority VOC도 즉시 2차에 동시 통보

벤더 escalation은 [POL-ESC-002]를 참조하세요.

## POL-ESC-002 | 벤더 Escalation 절차

내부 SOP로 해결 불가한 경우 또는 본 시스템 KB 범위 밖 ([POL-SCOPE-001]) 질의는 벤더 기술지원으로 escalation 합니다.

**적용 조건**
- 내부 SOP 모든 단계 실패
- 벤더 전용 진단 도구 필요
- HW 교체 결정 필요
- 본 KB가 다루지 않는 영역 (벤더 내부 파라미터, recipe fine-tuning 추천값 등)

**티켓 발행 절차** — [SOP-ESC-001]을 따릅니다.

**Tier 정의**
- **Tier 1 (Standard)**: 24시간 이내 응답
- **Tier 2 (Critical)**: 4시간 이내 응답 — Critical 알람이거나 라인 정지 영향 시
- **Tier 3 (Onsite)**: 24시간 이내 벤더 엔지니어 출동

**중요**: 본 시스템의 AI 응답 Agent는 KB 범위를 벗어난 질문에 대해 **"현재 지식베이스에서 근거를 찾을 수 없습니다"** 라고 답변하며, 본 정책에 따른 벤더 escalation을 안내합니다.

## POL-CHG-001 | 임계치 변경 신청 절차

임계치 변경은 안전·품질 영향을 평가한 후 시스템에 반영합니다.

### 1. 신청서 작성
시스템 내 `[임계치 변경 신청]` 메뉴에서 아래 항목을 입력합니다.
- 변경 대상 알람 코드 / 설비 ID
- 변경 전 값 / 변경 후 값
- 변경 사유 (정량적 근거 필수, 예: 최근 30일 false alarm rate)
- 영향 평가 (수율·안전·운영 영향)
- 검토자(1차 승인 PROC_ENG) 지정

### 2. 검토·승인 단계
- 1차 검토: 지정된 PROC_ENG (영업일 24시간 이내)
- 추가 승인: Severity별 추가 승인자 ([POL-PERM-002] 참조)

### 3. 적용
- 승인 즉시 시스템 반영 (수동 deploy 단계 없음)
- 적용 이력은 변경 history에 자동 기록 (2년 보존)

### 4. 사후 모니터링
- 신청자는 적용 후 **24시간 모니터링** 의무
- 24시간 내 false alarm rate가 변경 전 대비 +50% 초과 또는 누락 detection이 발생하면 자동 rollback

### 5. 거절 사유
- 정량적 근거 부족
- 안전·EHS 영향 평가 누락
- 직전 30일 내 동일 코드 임계치 변경 이력 (재변경 제한)

## POL-DATA-001 | 데이터 보존 정책

본 시스템의 데이터 보존 기간은 다음과 같습니다.

| 데이터 종류 | 보존 기간 | 비고 |
|---|---|---|
| Trend 원본 데이터 (1Hz) | 90일 | 90일 초과 시 1분 평균으로 다운샘플 |
| 알람 발생 이력 | 2년 | 메타데이터 포함 전량 보존 |
| VOC 이력 (처리 내용 포함) | 5년 | 첨부파일 포함 |
| 임계치 변경 이력 | 영구 | 신청서·승인자·rollback 포함 |
| 사용자 로그인 이력 | 1년 | 보안 감사용 |
| Recipe 변경 이력 | 5년 | 별도 시스템(MES) 연동 |

**다운로드 정책**
- Trend CSV 다운로드는 EQ_ENG 이상만 가능 ([POL-PERM-001]).
- 회당 다운로드 최대 1GB, 일일 누계 10GB 제한.

## POL-ACC-001 | 시스템 접근 권한 신청

신규 사용자 등록 또는 기존 사용자의 권한 변경 절차입니다.

### 신규 사용자 등록
1. 사번/이름/소속팀/희망 역할 정보로 사내 IT 포털에서 신청
2. 부서장 승인
3. IT 부서가 본 시스템 관리자에게 통보
4. 관리자가 시스템에 사용자 등록 (영업일 1일 이내)
5. 사용자에게 SSO 연동 안내 메일 발송

### 권한 변경 (역할 변경)
1. 본인 또는 부서장이 신청
2. 변경 후 역할의 권한 매트릭스([POL-PERM-001]) 사전 확인 필수
3. 부서장 승인 후 관리자 처리

### 권한 회수
- 퇴직/이동 시 사내 HR 시스템 연동으로 자동 회수 (실시간)

## POL-NIGHT-001 | 야간/주말 비상 대응 정책

정규시간 외(평일 18:00-09:00 및 주말/공휴일)에 Critical 알람이 발생한 경우의 대응 정책입니다.

### 호출 트리

```
Critical 알람 발생
  ↓ (즉시 자동 호출)
[1차] 야간조 EQ_ENG (해당 공정팀)
  ↓ (15분 내 응답 없으면)
[2차] 해당 공정팀 팀장
  ↓ (응답 불가 시)
[3차] 공정 PM (Process Manager)
  ↓ (필요 시)
[4차] 벤더 Tier 2 escalation
```

### SLA (야간/주말)
- **Critical 알람** 1차 응답: 5분 이내
- **High 알람**: 정규시간 시작 후 1차 응답 (긴급 시 야간 처리)
- **Medium 이하**: 정규시간에 처리

### 임시 운영 결정 권한
- 라인 정지/임시 운영 결정은 3차(공정 PM) 이상만 가능합니다.
- 야간조 EQ_ENG는 단독으로 라인 정지 결정을 할 수 없으며, 인명 안전 관련 사안(GAS-C-001 등)은 [SOP-GAS-001]을 우선합니다.

### 사후 보고
- 야간/주말 발생 사안은 다음 정규시간 시작 후 **4시간 이내** 보고서 작성.

자세한 SOP는 [SOP-ESC-002]를 참조하세요.

## POL-SCOPE-001 | 지식베이스 범위 (Out-of-Scope 명시)

본 시스템의 AI 응답 Agent가 다루는 KB 범위와 다루지 않는 영역을 명시합니다.

### KB가 다루는 영역
- 알람 코드 의미·임계치·일반적 원인
- 단계별 조치 절차 (SOP)
- 시스템 UI 사용법
- 권한·SLA·escalation 정책
- 데이터 보존·조회 정책
- 흔한 사용 문제 (FAQ)

### KB가 다루지 않는 영역 (Out-of-Scope)
다음 영역은 본 KB에 의도적으로 포함되지 않습니다.

1. **벤더 내부 진단/파라미터**: RF Matcher tune cap 추천값, HV PS ripple 보정 계수, 챔버 fine-tuning 파라미터 등은 벤더 소관입니다.
2. **Recipe 내용·최적화**: 특정 recipe의 파라미터 추천값, 공정 최적화는 본 KB 범위 밖이며 공정팀/벤더 영역입니다.
3. **보안 운영**: SSO 정책, 네트워크 방화벽 설정 등은 사내 IT 보안 정책 영역입니다.
4. **인사/조직**: 사번 조회, 인사 이력, 조직도 등은 본 시스템에서 다루지 않습니다.
5. **사내 다른 시스템**: MES, ERP, EHS 시스템의 동작은 각 시스템 매뉴얼 참조.
6. **물리적 정비 절차의 세부**: 부품 분해·조립 같은 hand-on 절차는 정비팀 작업지시서 영역입니다.

### Out-of-Scope 질문에 대한 표준 응답
본 시스템의 AI 응답 Agent는 위 영역에 해당하는 질문에 대해:
1. **추측·생성을 금지**합니다.
2. **"현재 지식베이스에서 근거를 찾을 수 없습니다"** 라고 명시적으로 답변합니다.
3. 적절한 escalation 경로([POL-ESC-002] 등)를 안내합니다.

이 정책은 본 시스템의 **답변 신뢰도**를 보장하는 핵심 원칙입니다.
